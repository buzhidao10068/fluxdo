# 4.4 复查：原生停止与异步完成语义修复

审阅及修复日期：2026-11-10。

基准文档：[4.4复盘(4.3)：证书隔离与生命周期修复.md](4.4复盘(4.3)：证书隔离与生命周期修复.md)。结合 `DeepSeek Harness/docs` 中的迁移、共存和证书复盘继续检查实际调用链，确认三项 P2 遗漏，现已补充本地源码修复及回归。Apple 原生编译、设备行为和 Rust 子模块交付尚未完成，不能据此认定已达到发版条件。

## 一、复查发现

### 1. Rust 的停止状态先于监听任务真正退出

4.4 的 Dart 层要求查询得到 `ok: true, running: false` 才允许更换 CA，但 Rust 原实现发送停止信号后就清除全局服务器及端口状态，没有等待实际监听任务退出。因此状态查询可能已经报告停止，旧 listener 仍占着端口。同端口重启可能失败；使用随机端口重启时，旧 listener 还可能短暂接受连接。

原实现的 broadcast 还可能在监听任务订阅前丢失停止信号。启动就绪依赖固定 200ms 延时，也不能证明 socket 已经绑定。仅模拟 Dart 状态响应的测试不能覆盖这些问题。

### 2. FFI 握手及 RPC 缺少等待期限，超时后的原生状态也未建模

原来的 isolate 握手和 `ReceivePort.first` 没有超时或退出通知处理。即使外层停止检查有一秒循环，只要内部状态 RPC 不回包，整个循环仍会永久等待。轮转队列和安装引导可能一直卡住。

单独增加 `Future.timeout` 也不充分：超时不会取消正在执行的原生调用。若旧 CA 启动迟到，再直接启动新 CA、建立另一个 worker 或回退进程，可能形成多代代理并行。复查还发现健康检查将坏响应视为已停止并清理本地状态；同配置重试也可能复用尚未确认的旧状态。

### 3. iOS 展示 Safari 即返回成功，未确认描述文件传输

原 `serveMobileconfigViaSafari` 在呈现 `SFSafariViewController` 后就回调成功。没有请求、超时、用户取消或发送失败，也可能让 Dart 进入“已下载”的后续步骤。socket 的单次 `send` 还可能短写；原流程缺少对完整请求、完整响应、失败和回调次数的统一管理。

成功条件应限定为完整 HTTP 响应已交给 socket。该条件仍不能证明 Safari 已保存描述文件，更不能代表系统已安装描述文件或已开启完全信任。

## 二、实际修复

### Rust：先释放 listener，再确认停止

涉及 `core/doh_proxy/src/ffi.rs` 和 `core/doh_proxy/src/proxy.rs`：

- 将停止通知改为保留最新状态的 watch channel，覆盖停止先于任务订阅的时序；每次启动创建新 server 实例。
- 分离 socket 绑定与监听循环。FFI 在绑定成功后才返回实际端口，绑定失败直接报告失败，删除固定延时推测就绪的逻辑。
- 保存监听任务的 `JoinHandle`，启停共用写锁。启动下一代前先停止并等待上一代退出；监听循环优先处理停止，返回前显式释放 listener 并清除本地地址。
- 停止最多等待监听任务三秒。超时保留任务句柄及尚未确认停止的状态，供下次继续等待；不提前清空状态，不覆盖旧任务。
- C 停止接口仍为 `void`，没有更改 ABI；Dart 仍需查询状态确认停止。

这里的停止保证针对监听 socket 和后续 accept。已接受的连接由独立任务处理，可能继续运行；本轮没有强制终止已有 CONNECT、TLS 或 HTTP 会话，也不把端口释放描述为已撤销所有旧 CA 连接。

### Dart：有限等待，并保留超时后的未知状态

新增 `lib/services/network/doh_proxy/ffi_worker.dart`，统一管理 isolate 通信：

- isolate 创建、握手及单次 RPC 均有等待期限，默认十秒。退出和未捕获错误会唤醒所有等待者，响应订阅和端口在结束时清理。
- 业务 RPC 超时只结束 Dart 等待，保留原 worker；迟到回包投递到已关闭的独立响应端口，不污染下一次调用。不能通过杀死 worker 推断原生调用已经取消。
- 只有确认 worker 已退出才允许重建。握手阶段尚未发送业务命令，超时可以清理该 isolate；创建超时后也会处理迟到的 isolate。

`DohProxyService` 的 FFI 调用改走统一 worker，并补齐状态约束：

- 启动、停止或健康查询异常后标记原生状态未知；此时禁止同配置直接复用和进程回退。
- 重试先发送停止，再得到明确的 `ok: true, running: false`，之后才允许传入新 CA 启动。停止始终执行验真；失败向上传播，不清理状态后假报成功。
- 健康检查响应失败时保留本地端口及运行记录供后续停止，不能把未知状态当作已停止。
- 停止轮询使用 `Stopwatch` 的单调计时，内部 RPC 也有界。十秒是单次通信的默认上限，并非整个 CA 轮转流程的总时限；多个阶段依次失败时总耗时可能更长。

### iOS：按实际发送结果完成一次回调

`ios/Runner/AppDelegate.swift` 新增同文件内的 `MobileconfigTransfer`，由 AppDelegate 持有当前会话，防止并发下载：

- 检查 Flutter 控制器可呈现且没有其他弹层；宿主已释放或界面不可呈现时明确返回失败。
- 在回环地址绑定随机端口，每轮使用独立 UUID 路径。检查 bind、listen 和 getsockname；分段读取完整 GET 请求，限制请求大小和读取时间，错误路径返回 404 后继续等待。
- 使用非阻塞 socket 和短周期 poll；会话默认三十秒截止，单连接请求读取最多五秒。处理短写、可重试错误、断连与 `SO_NOSIGPIPE`，只有响应头和 body 全部交给 socket 才返回成功。
- Safari Done、交互关闭、超时或传输失败返回失败。锁保护完成状态，只在主队列回调一次；失败仅关闭本会话创建的 Safari，socket 由后台任务统一关闭。

此修复不自动写入安装确认。描述文件传输、系统安装、完全信任和当前 CA 指纹确认仍是不同步骤。成功传输后 Safari 的实际行为、弹层关闭及重试体验仍需设备验收。

## 四、交付与验收边界

### Rust 子模块尚未形成远端交付

`core/doh_proxy` 是独立 Git 子模块。本轮只修改其工作区中的 `src/ffi.rs`、`src/proxy.rs`，未创建或推送子模块提交，也未更新主仓 gitlink。主仓的普通提交不会自动包含子模块内部未提交的源码；远端 CI 的 recursive checkout 只能取得已记录的子模块提交，不能取得本地脏文件。

后续交付必须先把这两个文件的修复提交到可获取的子模块远端，再由主仓更新对应 gitlink，并从干净 checkout 重建各平台 Rust 产物。当前本地测试通过不能证明远端 CI 或打包使用了这份修复。没有将这一发布步骤隐含标为完成。

### 继续沿用的边界

1. 指纹仅代表用户对当前 CA 的确认，不能探测系统安装、完全信任或之后的撤销。
2. Dart 全局信任添加仍为累加。系统已信任的旧 CA、描述文件、钥匙串项目、已有连接和进行中的请求不会自动撤销。
3. CA 双文件持久化仍非跨文件原子事务，未补完整 X.509 有效性及证书/私钥配对校验；实例加载后的外部文件更改没有持续监控。
4. 实际系统代理设置、`NetworkSettingsService` 与原生插件的完整集成、WebView 切换和真实签发链仍需设备验证。
5. 原生调用永久阻塞时只能有限等待并报告未知，不能承诺已经停止。之后的轮转会继续阻止新 CA 启动，直至能确认旧代理已停止。
6. macOS 钥匙串两版共存、Windows/Linux/Flatpak 安装与卸载、真实站点兼容性等 4.3/4.4 验收继续保持待执行状态。
