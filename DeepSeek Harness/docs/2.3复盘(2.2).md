## 一、复查结论

本轮未发现新的可确认缺陷。`2.2` 中两项链接入口问题的修复与实际调用链一致，定向测试和静态检查结果已复现。此结论覆盖本次列出的源码与本地验证范围，不代表全部站点迁移、Rust 原生交付或真机验收均已完成。

| 复核项 | 当前行为与证据 |
|---|---|
| 协议相对外链 | `isInternalUrlString` 仅将非 `//` 开头的 `/path` 视作站内相对路径；`//host/path` 按实际 host 判断并补全 HTTPS。`//bit.ly/t/123` 先提示短链风险，确认后访问 bit.ly，不执行本站话题回调。 |
| 站内推广链接 | 相对、绝对、协议相对地址先以补全后的 URL 分类；blocked、dangerous、risky 在用户、workspace、聊天、话题、图片、附件等快捷分支前检查。`/t/123?aff=456` 等地址不会再直接跳过提示。 |
| 取消、重复确认及生命周期 | 取消后不导航、不下载、不调用话题回调；完成入口检查后复用私有打开方法，避免重复确认。异步弹窗结束后检查 `context.mounted`，原入口销毁后停止后续导航。直接外链入口仍保留完整安全检查。 |
| 正常站内及媒体行为 | 普通站内话题保留原生回调和 slug、楼层参数；附件保留完整目标 URL；站点/CDN 图片继续使用图库及既有 S3/CDN 重写。 |
| 真实内容入口 | 已沿正文渲染器、`fluxdo_render_callbacks.dart`、launcher，以及附件和 onebox 入口核查链接传递。mention 与 lightbox 的原生处理分支未证实会访问外部网页并绕过本次确认，未将其列为新缺陷。 |

本轮没有进一步修改 launcher 的业务逻辑。`2.2` 的历史发现和修复前复现记录继续保留，以便区分旧错误行为与修复后的验收结果。
