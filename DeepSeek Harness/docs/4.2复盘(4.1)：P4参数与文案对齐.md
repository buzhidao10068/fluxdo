## 一、复盘结论（修复前）

确认 4 项迁移遗漏。上传参数、最小字数和文案相关回归通过，但桌面版尚未完成与原版的应用隔离。部分实现沿用自原版，因此这里记录的是当前迁移尚未补齐的内容，不将其全部归因为 P4 新引入的回归。

### 1. P1：Windows 安装身份未隔离

`windows/setup.iss:7` 的 AppId 与原版一致，默认安装目录仍为 `FluxDO`，程序组和快捷方式也使用相同名称。Inno Setup 会复用同一产品的安装、卸载身份，默认路径中的文件也会被覆盖，无法独立共存。

安装、卸载前按进程名执行 `taskkill /f /im fluxdo.exe`，还会结束正在运行的原版。

修复要求：独立安装器 GUID、安装目录、快捷方式和进程识别。可见应用名仍可保留 FluxDO。

### 2. P1：本地数据目录未隔离

存在两个独立成因：

- `windows/runner/Runner.rc` 的 CompanyName/ProductName 仍为 `com.example`/`FluxDO`。锁定版本的 path_provider_windows 据此构建 `%APPDATA%\com.example\FluxDO`，两版共享偏好设置、安全存储文件和 WebView2 用户目录。
- `CookieJarService.initialize()` 和 `AppDatabase._initialize()` 直接使用 Documents 下的 `.cookies`、`hive`。普通 Windows、Linux，以及当前关闭沙盒的 macOS 构建均未获得应用专属子目录，修改包名或 bundle identifier 不会自动隔离这些数据。

退出登录调用 CookieJar 的 `clearAll()`，会删除共用的持久 Cookie 文件。Hive 还存在同用户名缓存混用、草稿共用和并发争用的风险。Cookie 的域匹配规则仍然存在，这不等于 Cookie 会直接跨域发送。

修复要求：建立 fork 专属目录，同步更新读取、迁移、统计与清理入口；明确旧数据处理策略。只改安装目录或 Windows VERSIONINFO 不足以修复全部问题。

### 3. P2：Windows 深链实例识别可能命中原版

`windows/runner/main.cpp` 使用固定窗口类 `FLUTTER_RUNNER_WIN32_WINDOW` 和窗口标题 `FluxDO` 查找运行实例，随后转发链接并退出。原版运行时，即便系统正确启动 fork，也可能把 `discourse://` 授权回调转发给原版，导致 fork 无法完成登录。

修复要求：窗口注册和查找使用同一份 fork 专属实例标识。此问题独立于操作系统对共用 URL scheme 的处理程序选择。

### 4. P2：Windows 通知注册与回调身份未隔离

`lib/services/local_notification_service.dart` 仍使用原版 AUMID `Com.FluxDO.FluxDO` 和通知回调 GUID `e965ef8c-b676-47c1-b6e7-297d63942974`。

核对锁定依赖 `flutter_local_notifications_windows 3.0.0` 的 `src/plugin.cpp`：`UpdateRegistry()` 按 AUMID 写入当前用户的 PushNotifications/Backup、Classes/AppUserModelId 项及 CustomActivator；`RegisterCallback()` 按 GUID 调用 `CoRegisterClassObject()` 注册 COM 回调。同名应用会共用通知身份，存在通知归属或点击回调冲突风险，仅改安装器、可执行文件和窗口类不能解决。

修复要求：AUMID 和回调 GUID 均独立，并在 fork 后续升级中保持稳定。该版本插件在运行时完成上述注册，没有要求本轮额外在安装器快捷方式中重复注册。冷启动点击及安装卸载行为仍须在原生环境实测。

## 四、追加：数据升级策略

- 从旧共享路径的桌面版本升级后需要重新登录；旧草稿、设置及其他共享数据不自动接续，升级前应自行导出或保存需要保留的内容。
- 不自动读取、搬迁或删除归属不明的旧 Documents/Temporary/Support 共享数据，也不从原版 macOS Keychain service 自动导入凭据。旧文件保留在原处。
- 新目录内的历史结构仍由应用自身迁移处理，迁移和清理限定在 fork 范围；主动下载继续使用公共目录和原回退规则。
- `fluxdo` / `discourse` scheme 继续共用。独立窗口类能避免 fork 自己把链接转发给原版，系统最终选择哪个应用、安装卸载后 handler 是否有效仍需验收。
