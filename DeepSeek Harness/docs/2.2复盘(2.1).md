## 一、复查结论

发现两项可复现的链接入口问题。`LinkSecurity.checkUrl` 的分类测试虽然通过，但不能证明点击正文链接时执行了安全确认。两项问题来自既有 launcher 分支顺序，使本次 P1 新配置声明的短链和推广链接提示在部分实际入口中失效。

### 1. [P1] 协议相对外链被当成站内链接

位置：`lib/utils/link_launcher.dart` 的 `isInternalUrlString` 与 `launchContentLink`。

旧判断 `if (url.startsWith('/')) return true` 同时接受 `/t/123` 和 `//bit.ly/t/123`。后者具有独立的外部主机，不能只按首字符认作站内。

已复现的旧行为：

- `//bit.ly/t/123` 直接执行本站话题回调，话题 ID 为 123，既忽略外部主机，也未弹短链风险确认。
- `//bit.ly/abc?aff=123` 直接打开 `https://bit.ly/abc?aff=123` 的 WebView，未弹危险提示。

正文渲染器保留原始 href，`lib/utils/fluxdo_render_callbacks.dart` 将其传给 `launchContentLink`，因此问题可由实际正文链接触发，不限于直接调用工具方法。

### 2. [P2] 站内快捷跳转绕过推广链接危险提示

位置：同文件的 `launchContentLink`，以及 `lib/config/sites/nodeloc.dart` 的 `dangerousDomains: ['**aff=']`。

既有分类优先级为“阻止 > 危险 > 风险 > 信任 > 内部”，`test/utils/link_security_test.dart` 已要求 `aff=` 优先于内部域名。但用户、workspace、聊天、话题、图片、附件和普通站内分支在最后的 `launchExternalLink` 安全检查之前返回。

已复现的旧行为：

- `https://www.nodeloc.com/t/123?aff=456` 的分类为 dangerous，点击却直接执行话题回调。
- `https://www.nodeloc.com/?aff=123` 的分类为 dangerous，点击却直接打开 WebView。

相对路径也需要用补全后的 URL 进行分类，避免 `/t/123?aff=456` 因缺少 host 而退化为 normal。
