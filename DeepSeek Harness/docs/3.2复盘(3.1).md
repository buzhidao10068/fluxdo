## 二、确认问题

### 1. P1：Windows CDP 异步读取后缺少会话代次复查

相关位置：

- `lib/services/network/cookie/boundary_sync_service.dart:146`：入口检查 `requestGeneration`。
- `lib/services/network/cookie/boundary_sync_service.dart:155`：Windows 且传入控制器时直接进入 CDP 分支，没有把代次检查传入实际写入路径。
- `lib/services/network/cookie/cookie_jar_service.dart:889`：异步读取 CDP Cookie 快照。
- `lib/services/network/cookie/cookie_jar_service.dart:906`：调用 `shouldSyncCookie`；对应判定在 `boundary_sync_service.dart:419` 对非 `cf_clearance` Cookie 直接放行，不能代替认证会话检查。
- `lib/services/network/cookie/cookie_jar_service.dart:932`：持久化快照前没有再次检查代次。

触发顺序为：旧登录开始同步并等待 CDP 返回；用户退出，推进 `AuthSession` 并清空 jar；旧读取返回 `_t`；CDP 路径继续持久化。`syncFromWebView` 自身的锁只串行化同步请求，不能替代与退出清理之间的协调。通用分支在 `boundary_sync_service.dart:351` 有写入前复查，Windows 分支绕过了这段逻辑。

本轮在 Windows 上使用真实 `EnhancedPersistCookieJar` 和可控 CDP 返回值复现：

1. 阻塞 `Network.getCookies` 对应的快照读取。
2. 执行 `AuthSession().advance()`，再执行 jar 的 `deleteAll()`，确认 `_t` 为空。
3. 释放旧快照，返回 `_t=old-session`。
4. 等待同步结束，确认原代次已经失效，但 jar 中 `_t` 又变为 `old-session`。

日志标记：`REVIEW_P2_CDP_GENERATION`，见 `build/review_p2/probe.log`。

探针重放了真实 `logout` 的关键顺序：`lib/services/discourse/_auth.dart:1642` 先推进代次，`:1697` 再清理 Cookie。探针没有调用完整的登出网络请求和 UI 广播，也没有证明任意新令牌都会被覆盖；确认的事实是旧读取可以在清理后恢复认证 Cookie。后续成功结果即使被代次检查拒绝，也不能撤销已经发生的 jar 写入。

建议将会话有效性检查传入 CDP 实际持久化路径，在异步读取结束后和写入前复查，并明确写入与退出清理的串行关系。修复回归必须让代次变化发生在 CDP 读取已经发出之后，且覆盖持久化 jar。

归属：`boundary_sync_service.dart`、`cookie_jar_service.dart` 当前相对 HEAD 无改动，属于既有缺口。mini 在 `webview_login_dialog.dart:707` 传入了 `requestGeneration`，但底层 Windows 实现未完整落实该约束。

### 2. P2：备用码 / 安全密钥的网页登录交接存在路由竞争

相关调用链：

1. `lib/pages/login_page.dart:174` 将真实 `showTwoFactorDialog` 传给 mini，`:177` 在备用码回调中立即调用 `_loginWithWebView()`。
2. `lib/widgets/auth/two_factor_dialog.dart:100` 先关闭 TOTP 对话框，再于下一行同步调用备用码回调。
3. `lib/pages/login_page.dart:235` 向同一 Navigator 推入返回类型为 `bool` 的网页登录路由。
4. mini 在 `lib/widgets/auth/webview_login_dialog.dart:632` 等待的 TOTP 结果随后返回 `null`，于 `:644` 调用 `_finishCanceled()`。
5. `webview_login_dialog.dart:758` 使用 `Navigator.of(context).pop(WebViewLoginDialogResult.canceled())`，此时栈顶已经是刚打开的网页，而不是 mini。

本轮探针使用真实 mini、真实 TOTP 对话框和真实按钮点击，网页登录内容替换成同样返回 `bool` 的简单页面。点击“改用备用码 / 安全密钥”后，Flutter 调试测试得到：

```text
A request was made to pop a route with a result of type WebViewLoginDialogResult,
but the route expected a value of type bool.
```

同时 mini 返回 Future 尚未完成。日志标记：`REVIEW_P2_BACKUP_ROUTE`，见 `build/review_p2/probe.log`。

这证明切换过程的路由目标和结果类型错误；没有执行真实网页登录，也不据此宣称各平台发布构建都会以同样方式抛错。`3.1` 中“备用码及安全密钥沿用已有 UI 处理和网页登录兜底”描述了意图，当前交接实现尚不能作为可用兜底验收。

建议让 2FA 返回明确的“输入验证码 / 取消 / 切换网页登录”结果，由调用方在 mini 完成退出后打开网页登录。不要在 TOTP 的同步按钮回调中同时退出旧流程和推入新路由，也不要仅用固定延迟掩盖顺序问题。修复后需要点击真实按钮，断言只关闭对应对话框、网页保持打开且 mini 正常完成。

归属：备用码回调、同步 push 和 mini 收到空结果后 pop 的结构在 HEAD 中已经存在；`two_factor_dialog.dart` 本轮无改动。属于既有路径缺陷。

### 3. P2：系统返回关闭 mini 后，异步成功收尾仍能写入 Cookie

相关位置：

- `lib/widgets/auth/webview_login_dialog.dart:83` 使用 `showDialog`；`barrierDismissible: false` 约束遮罩点击，没有阻止系统返回。
- `webview_login_dialog.dart:136` 的 `dispose()` 只释放控制器，没有使流程取消或失效。
- `webview_login_dialog.dart:655` 在成功收尾刚开始时设置 `_finished = true`，该标记用于去重，无法表达后续取消。
- `webview_login_dialog.dart:674` 至 `:709` 的 Cookie 读取、bootstrap 和边界同步之间没有独立的生命周期取消检查。
- `webview_login_dialog.dart:736` 最后的 `mounted` 只保护路由操作，不能阻止此前的 Cookie 写入。

触发顺序为：收到成功响应，mini 开始等待原生 `_t` 读取；用户系统返回，路由退出并返回 `null`；已发出的读取稍后返回；由于取消没有推进全局会话代次，成功收尾继续 bootstrap 和同步。

本轮使用 Flutter 框架的 `tester.binding.handlePopRoute()` 模拟系统返回，探针确认路由已经结束、mini 结果为 `null`，再释放 Cookie 读取。最终 `AuthSession` 代次没有变化，jar 中出现 `canceled-login-session`。日志标记：`REVIEW_P2_CANCEL`，见 `build/review_p2/cancel_probe.log`。

验证限制：本项使用内存 jar，模拟控制器的 `dispose()` 是空实现，重放的是“原生读取已经发出，销毁后仍返回”的时序；没有证明所有真机 WebView 都会保留该返回。持久化 jar 与 widget 组合的早期探针因测试异步 I/O 等待未结束而被中断，不计为通过，也不作为业务挂死证据。

建议把“成功收尾进行中”和“用户已取消 / 组件已销毁”分开表达，让系统返回、关闭按钮和 `dispose` 都能使本流程失效。取消状态应穿过异步读取、bootstrap 和实际持久化边界；仅在最后检查 `mounted` 不足以防止写回，也不宜仅为关闭一个弹窗而使所有全局会话请求失效。

归属：HEAD 中已有“销毁不取消异步收尾”的生命周期缺口。本轮增加的有界 Cookie 等待扩大了需要检查的异步范围，但没有补齐独立取消语义。此项与第一项分别涉及同代次内用户取消、跨代次会话退出，需要分别回归。

### 6.1 Windows CDP 与通用同步共同阻止失效快照写回

相关文件：

- `lib/services/network/cookie/boundary_sync_service.dart`
- `lib/services/network/cookie/cookie_jar_service.dart`
- `packages/enhanced_cookie_jar/lib/src/enhanced_persist_cookie_jar.dart`

`syncFromWebView` 在调用时捕获会话代次和 Cookie 清理代次，并接受单个流程的 `isCancelled`。即使调用方没有显式传入 `requestGeneration`，也使用调用时的当前会话代次。三项条件共同决定快照能否继续写入。

有效性检查同时覆盖 Windows CDP 和 CookieManager：读取返回后、异步过滤后、实际取得写入锁后，以及底层持久化队列开始执行和异步读盘后均复查。CDP 返回时流程若已失效，直接结束，不再回退 CookieManager 重新读取。认证 Cookie 规范化和 CF 确认值原子替换也接收相同检查，避免主保存被取消后，后续规范化仍继续写入。

`CookieJarService.writeFromWebView` 与 `clearAll` 共用实际写入锁。`clearAll` 在开始时立即推进清理代次，让已经发出的快照失效；锁不包住 CDP / CookieManager 快照读取，因此退出清理无需等待读取返回。如果持久化已开始，清理排在该写入之后执行，保证清理完成后内存与磁盘均为空。

底层 `saveCanonicalCookies`、`saveFromCdpCookies`、`saveFromResponseTrusted` 和 `replaceByNameForSite` 新增可选 `shouldWrite`，不改变标准 `CookieJar.saveFromResponse` 接口。检查后到缓存更新前没有新的异步等待；已开始的持久化不会因后来取消而回滚。这一边界由退出清理的串行顺序保证，不能将取消回调理解为事务回滚。

### 6.2 2FA 返回明确动作，由登录页完成网页登录交接

相关文件：`lib/widgets/auth/two_factor_dialog.dart`、`lib/widgets/auth/webview_login_dialog.dart`、`lib/pages/login_page.dart`。

2FA 对话框使用 `TwoFactorResult` 区分验证码和切换网页登录，取消仍返回 `null`。“改用备用码 / 安全密钥”按钮只关闭当前 2FA 对话框并返回切换动作，不再直接推入网页。

mini 收到切换动作后，使自身流程失效并返回 `WebViewLoginDialogResult.useWebView`。`showWebViewLoginDialog` 等待对应路由的 `completed`，确认退出动画和 overlay 清理结束；随后 `LoginPage` 才打开返回类型为 `bool` 的完整网页登录页。交接依赖路由完成信号，没有增加固定延迟。

正式 widget 测试点击真实备用码按钮，使用真实 `LoginPage`、TOTP 对话框和 `WebViewLoginPage` 路由，确认网页保持打开、两个对话框已退出、没有路由类型异常；从网页返回后仍保留登录表单。测试模拟 WebView 平台，没有执行真实备用码或安全密钥验证。

### 6.3 mini 的取消状态穿过异步收尾与持久化边界

相关文件：`lib/widgets/auth/webview_login_dialog.dart`。

保留 `_finished` 用于去重，另用 `_cancelled` 和取消信号表达流程失效。系统返回通过 `PopScope` 在 pop 时立即失效，标题关闭与 `dispose` 也执行相同失效动作。成功收尾已经开始时，标题关闭仍可取消；关闭单个 mini 不推进全局 `AuthSession` 代次。

本次 `_t` 读取、重试延时、bootstrap、边界同步、诊断和最终结果之间均检查流程有效性。bootstrap 接收取消回调与信号，Cookie 同步把局部取消传到底层写入检查。迟到的脚本回调和页面就绪回调也受流程状态约束。两处异步后的导航保留显式 `mounted` 检查，避免新增静态检查提示。

新增测试在首次读取及最终同步两个阶段分别执行系统返回和标题关闭，并在退出动画尚未销毁 widget 时释放迟到快照，验证 pop 当时就已取消。另有销毁后返回快照的回归。各项均断言不恢复认证 Cookie，系统返回和标题关闭测试还核对全局会话代次不变。
