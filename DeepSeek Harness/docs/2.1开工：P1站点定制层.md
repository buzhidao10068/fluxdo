## 三、链接策略与匹配修正

`nodelocCustomization.linkSecurityConfig` 保持普通外链确认开启：

- `*.nodeloc.com` 覆盖裸域、www 及多级子域，伪装后缀和 userinfo 不会被当成站内域名。
- 保留通用本机、`.local` 和私网规则，包括回环、链路本地及 RFC1918 IPv4 范围。
- 通用短链接名单与 `**aff=` 推广关键词规则沿用已有客户端策略。短链显示风险提示，推广关键词显示危险提示。
- `trustedDomains`、`blockedDomains` 保持为空。未取得 NodeLoc 外链盾的真实名单，不将页脚链接或旧站合作域名直接标记为可信或屏蔽。
- `linux.do`、`ldstatic.com`、旧站信任域与屏蔽域在 NodeLoc 下回到普通外链确认。

通用短链和推广关键词是本地防护选择，不应描述成“已完整复刻 NodeLoc 主题配置”。已确认公开页面含外链确认功能，但尚未确认其全部服务端设置。

旧私网规则使用 `^regex`，匹配器实际会移除规则前缀并在**完整 URL** 上查找；只写 IP 片段既可能误中 URL 的路径或查询，也缺少主机终止边界。本次仅在 NodeLoc 配置中补齐 scheme、URL 起点、可选 userinfo、端口和主机边界。规则开头的 `^^` 分别表示规则类型前缀及正则起点。

未改变 `LinkSecurity` 通用匹配器的正则或路径语义，也未修改保留的 Linux.do profile。测试覆盖私网边界、非法 IP、伪装主机、路径和查询内嵌 IP、协议相对地址，并验证“阻止 > 危险 > 风险 > 信任 > 内部”的既有优先级。

## 四、DNS / ECH 与原生交付状态

DNS 预热只从以下值提取主机：`AppConstants.baseUrl`，以及 `PreloadedDataService` 的 `longPollingBaseUrl`、`cdnUrl`、`s3CdnUrl`、`s3BaseUrl`。支持 HTTP/HTTPS、协议相对 URL、首尾空白、去重和排序；缺失、相对路径、非 HTTP 和无效 URL 被忽略。没有资源配置时仅预热 `www.nodeloc.com`，不再合成 connect/ping/cdn/credit/cdk 等旧站主机。

Dart ECH 内置根域为 `nodeloc.com`，覆盖其子域；旧 `linux.do` / `ldstatic.com` 默认不再走公共 ECH 查询名。用户自定义域、开关及序列化能力保留，设置页测试已同步。

## 五、polyfill 同步与构建限制
