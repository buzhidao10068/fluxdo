## 0. 总判断

P0 方向是对的：把 `baseUrl`、`siteCustomization`、深链/剪贴板 host 从硬编码改成从 `baseUrl` 派生（新增 `siteHost` / `siteRootDomain` / `isSiteHost`），这比全局查找替换健康。`nodeloc.dart` 的注释也写清了"为什么 plugins 必须为空"。

但执行上有 **1 处致命硬伤 + 1 处系统性漏改**，而 `复盘1.1` 只看到了表层症状：

1. **致命**：剪贴板新正则把 raw string 改成了普通字符串，转义全部丢失，`RegExp` 构造直接抛 `FormatException`，剪贴板检测**静默彻底失效**（不是"一条测试挂"）。
2. **系统性**：`baseUrl` 换成带 `www` 的域名后，全仓 7 处 `Uri.parse(baseUrl).host` 派生的"主域 + 子域"判定集体退化成"只认 `www.nodeloc.com`"；新派生工具只推广到了 2 个服务，其余一个没动。

对 `复盘1.1` 的 13 条逐条结论：**9 条认可（其中 4 条需补充）、2 条结论已过时、2 条事实判断有误**。详见 §8。

## 2. 致命问题：剪贴板正则转义全部丢失（复盘1.1 未发现）

### 2.1 改动对比

```dart
// main —— raw string，反斜杠保留
static final RegExp _linuxDoUrlRegex = RegExp(
  r'(?:(?:https?:)?//)?(?:www\.)?linux\.do(?::\d+)?/[^\s<>"\]\)）}】》]+',
  caseSensitive: false,
);

// P0 —— 普通字符串拼接，反斜杠被语言吃掉
static RegExp _buildSiteUrlRegex() {
  final root = RegExp.escape(AppConstants.siteRootDomain.toLowerCase());
  return RegExp(
    '(?:(?:https?:)?//)?(?:www\.)?' + root + '(?::\d+)?/[^\s<>"\]\)）}】》]+',
    caseSensitive: false,
  );
}
```

位置：`lib/services/clipboard_topic_link_service.dart:29-36`。

### 2.2 为什么必坏

Dart 规范中非 raw 字符串的词法规则（`<STRING_CONTENT_COMMON>`）：

```
<STRING_CONTENT_COMMON> ::= ~(\ | ' | " | $ | \r | \n)
  | <ESCAPE_SEQUENCE>
  | '\' ~(n | r | b | t | v | x | u | \r | \n)
```

语义说明：**`\k` 表示字符 `k`，对任意 k ∉ {n, r, f, b, t, v, x, u}**。也就是说 `\d`、`\s`、`\.`、`\]`、`\)` 都是**合法写法**，但反斜杠会被丢弃，只留下 `d` / `s` / `.` / `]` / `)`。`[规范]`

`RegExp.escape()` 返回的是运行时字符串（`nodeloc\.com`），反斜杠作为**数据**保留，所以 `root` 部分是好的；坏的是两段字面量。

### 2.3 还原后的真实 pattern `[探针]`

用脚本按上述规则还原并交给正则引擎编译：

```
(?:(?:https?:)?//)?(?:www.)?nodeloc.com(?::d+)?/[^s<>"])）}】》]+
```

→ **`unbalanced parenthesis at position 55`**，编译失败。具体三处崩坏：

1. `[^\s<>"\]\)...]` 里的 `\]` 变成 `]`，字符类在 `"` 之后被提前闭合，后面的 `)` 成了无主的右括号；
2. `(?::\d+)?` 变成 `(?::d+)?`，端口不再匹配；
3. `(?:www\.)?` 变成 `(?:www.)?`，`.` 变通配符。

### 2.4 实际影响（比"一条测试挂"严重得多）

- `_siteUrlRegex` 是 `static final`，`FormatException` 在**首次调用 `findFirstTopicLink` 时**抛出；
- `checkClipboard()` 外层是 `catch (_) { return null; }` → **异常被完全吞掉**，剪贴板话题链接提示静默失效，无日志、不崩溃、线上无从察觉；
- 测试里直接调 `findFirstTopicLink` → 抛异常，`test/services/clipboard_topic_link_service_test.dart` **整个文件全红**，而不只是 `复盘1.1` 指出的那一条断言。

### 2.5 为什么工具链没拦住

- `flutter analyze` 抓不到：`unnecessary_string_escapes` 只针对 `\"` / `\'` 这类**可转义字符**，`\d` 不在其列表内，不报警；
- `[静态]` `.github/workflows/build.yaml` 只在 `v*` tag 时构建，**没有 analyze / test 步骤**；
- 于是这类错误可以直接发版。

> `复盘1.1` 第 1 条说"新正则匹配不到 `WWW.LINUX.DO`，`expect(candidate, isNotNull)` 必然失败"——**症状描述对，归因不对**：真正原因是正则本身已经坏了，测试输入只是第一个撞上的地方。第 11 条说"正则派生时域选取有逻辑错位"也没摸到这里。

## 3. 系统性问题：`www` 前缀打穿 7 处 host 判定（复盘1.1 未定位）

`baseUrl` 从 `https://linux.do` 变成 `https://www.nodeloc.com` 后，所有 `Uri.parse(baseUrl).host` 派生的判断从"匹配整个 `linux.do`（含全部子域）"退化为"只匹配 `www.nodeloc.com`"。P0 只把新工具用在了**深链 + 剪贴板**两处：

| 判定点 | 实现 | 裸域 `nodeloc.com` | 子域 `meta.nodeloc.com` | 备注 |
|---|---|---|---|---|
| `lib/constants.dart:313` `isSiteHost` | 新派生 | ✅ | ✅ | 仅深链使用 |
| `lib/services/clipboard_topic_link_service.dart:175` `_isAllowedHost` | 新派生 | ✅ | ❌ | 有意排除子域 |
| `lib/services/dio_http_client.dart:104` `_isMainDomain` | **旧逻辑** | ❌ | ❌（原本 ✅） | 主域/子域分流 |
| `lib/services/network/cookie/cookie_jar_service.dart:834` `matchesAppHost` | **旧逻辑** | ❌ | ❌（原本 ✅） | cookie 归置核心 |
| `lib/utils/link_launcher.dart:31` `isInternalUrl` | **旧逻辑** | ❌ | ❌（原本 ✅） | 站内/站外判定 |
| `lib/services/network/webview/webview_adapter_settings_service.dart:89` `canUseWebView` | **旧逻辑** | ❌ | ❌ | 本来只认主域 |
| `lib/pages/search_page.dart:38` `normalizeDirectSearchLink` | **仍硬编码 `linux.do`** | ❌ | ❌ | 正则里写着 `linux\.do` |

### 3.1 具体后果

1. **裸域链接只被深链认**。NodeLoc 裸域 301 到 www，用户分享/粘贴 `nodeloc.com/t/123` 极常见；`isInternalUrlString` 会判成外链 → 弹外部链接确认框；搜索框粘它也不会直达话题，退化成普通搜索。
2. **子域 cookie 被当成"非本站"丢掉**（高风险，需实机确认）。`matchesAppHost` 现在只认 `www.nodeloc.com` 与 `*.www.nodeloc.com`（后者现实中不存在）。Cloudflare 的 `cf_clearance` 通常按 zone 顶点下发 `Domain=.nodeloc.com`，按此逻辑会被 `lib/services/cf_clearance_refresh_service.dart:721`、`lib/services/browser_trust_coordinator.dart:736` 判为不可信 → CF 通行证丢失。
   `[实测]` 当前 NodeLoc 未下发挑战、`/session/csrf` 与 `/session/hp.json` 都只发 host-only 的 `_forum_session`（`path=/; secure; HttpOnly; SameSite=Lax`，无 `Domain`），所以平时不显形；但一旦真触发挑战就会踩中。
3. `lib/services/discourse/_uploads.dart:153` 的 `isAppHost`、`dio` 的主域分流同理会收窄。
4. `[实测]` `_forum_session` 是 host-only cookie，恰好被 `www` 主域接住，所以**登录态本身暂时不坏**——这也是问题不容易被发现的原因。

### 3.2 结论

`复盘1.1` 第 9 条（两个服务口径不一致）、第 11 条（两套语义并行）方向对，但没指出**根因是 www 前缀**，也没给出这 7 处清单。真正的修法不是"再补一个 host 工具"，而是**把所有 host 判定收敛到 `siteRootDomain`**，一次解决裸域 + 子域 + cookie 三个问题。

## 7. 架构：违背了规划文档自己给的路线

### 10.2 正则转义还原（`[探针]`）

按 Dart 规范把 `\k → k`（k ∉ {n,r,f,b,t,v,x,u}），拼接 `RegExp.escape` 的运行时值后交给正则引擎编译，得到 `unbalanced parenthesis`。等价校验脚本（Python，模拟同一规则）：

```python
BS = chr(92)
simple = {'n':'\n','r':'\r','f':'\f','b':'\b','t':'\t','v':'\v'}
def unescape(s):
    out, i = [], 0
    while i < len(s):
        if s[i] == BS and i + 1 < len(s):
            n = s[i+1]
            if n in simple: out.append(simple[n])
            elif n in 'xu':  out.append('<'+n+'>')
            else:            out.append(n)      # \k -> k
            i += 2
        else:
            out.append(s[i]); i += 1
    return ''.join(out)
```
