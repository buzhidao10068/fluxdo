# 复盘1.1：P0站点身份改造

## 总体判断

P0 分支只有 1 个提交 `819341ef`（8 个文件、+139/-74），做的是「站点身份从 linux.do 换成 www.nodeloc.com」。方向是对的：把 `baseUrl`、`siteCustomization`、深链/剪贴板 host 从硬编码改成从 `baseUrl` 派生（新增 `siteHost`/`siteRootDomain`/`isSiteHost`），这是比"全局查找替换"更健康的做法，值得肯定。

但按「有没有改得不好」来挑，问题不少，分五类：

---

### 一、会直接失败/测试退化的硬伤

**1. 剪贴板测试有一条输入没跟着改，测试必挂**

`lib/services/clipboard_topic_link_service.dart` 的正则已经改成从 `AppConstants.siteRootDomain`（= `nodeloc.com`）派生，但 `test/services/clipboard_topic_link_service_test.dart` 的用例「保留 query 和 fragment，并统一 scheme 与 host 大小写」里，**输入仍是 `看看 HTTPS://WWW.LINUX.DO:443/...`，只改了期望输出**。新正则匹配不到 `WWW.LINUX.DO`，`expect(candidate, isNotNull)` 必然失败。典型的"改了输出没改输入"。

**2. deep_link 测试把裸域用例替换成了重复用例**

`test/services/deep_link_service_test.dart` 里 `canHandleUri` 头两条断言原来是 `https://linux.do/t/123`（裸域）和 `https://www.linux.do/t/123`（带 www），全替换后**两条变成完全相同的 `https://www.nodeloc.com/t/123`**。结果：一条冗余重复断言，同时**裸域 `nodeloc.com` 的覆盖被弄丢了**。而裸域本身是 `isSiteHost` 要支持的关键场景。

---

### 二、迁移不彻底（半成品，会埋雷）

**3. 原生登录页仍用 linux.do 的 hcaptcha sitekey**

`lib/pages/login_page.dart` 完全没动：`_kLinuxDoHcaptchaSiteKey` 还是 linux.do 的 sitekey，`_loginWithWebView('https://linux.do/password-reset')` 还指向旧站，标题硬编码 `'LINUX.DO'`。换站后 hcaptcha 校验大概率失效——这是实打实的功能不匹配，P0 最应该一起改的。

**4. DoH/ECH 与网络设置白名单仍全是 linux.do 系域名**

- `lib/services/network/doh/ech_dns_policy.dart`：`builtinDomains = ['linux.do', 'ldstatic.com']`
- `lib/services/network/doh/network_settings_service.dart`：`connect/ping/cdn/credit/cdk.linux.do`

如果应用走自建 DoH，`nodeloc.com` 不在内置域/白名单里，加密 DNS 和连通性策略对新站基本不生效。

**5. 用户可见文案几乎全未更新**

`.arb` 语言包里 `about_legalese`、登录标题、剪贴板开关描述、邀请分享主题、代理测试文案、reward 提示等**仍全部写 "Linux.do"**；`README.md`、flatpak 元数据、`devtools_extension/lib/src/tabs/actions_tab.dart` 默认 URL、`assets/polyfill/compat-polyfill.js` 的 `*.ldstatic.com` 白名单也都还在。App 内部会持续把自己描述成 Linux.do 客户端。

**6. `linuxdo.dart` 变成死代码**

`lib/config/sites/linuxdo.dart` 在 P0 分支上已经**没有任何 import**（`git grep sites/linuxdo` 零匹配），但文件保留不动。要么删、要么作为"多站点候选"存档，现在是无归属的遗留负担。

---

### 三、安全/功能降级（nodeloc 配置被"清空式兜底"）

**7. 链接安全策略从"有名单"退化成"只有 internal"**

`lib/config/sites/nodeloc.dart` 的 `trustedDomains`/`riskyDomains`/`dangerousDomains`/`blockedDomains` **全部为空列表**。对照 `lib/config/sites/linuxdo.dart`，这意味着：短链服务（bit.ly 等）不再告警、`**aff=` 推广链检测消失、阻断域失效。注释写"待站方主题配置采集后补全"——能理解，但在 P0 上线就是安全防护的净退步。

**8. internalDomains 丢掉了 `*.local`**

linuxdo 版 internalDomains 含 `*.local`，nodeloc 版没有。虽然 `lib/utils/link_security.dart` 的 `isLocalIp` 能兜住 `.local` 主机名，但规则层语义变窄，外链确认弹窗行为会变。

---

### 四、设计一致性

**9. 两个服务对"合法 host"口径不一致**

同一个提交里：
- 剪贴板 `lib/services/clipboard_topic_link_service.dart` 的 `_isAllowedHost` 只认 `www.nodeloc.com` 和裸域，**明确排除子域**（`meta.nodeloc.com` 不触发）；
- 深链 `lib/services/deep_link_service.dart` 的 `isSiteHost` **接受任意子域**（`meta.nodeloc.com` 照接）。

两个服务对"什么算本站链接"各自拍板，缺少一个统一的 host 策略层。这类分叉在 `main` 里就有，P0 只是把硬编码换成了派生，没有收敛。

**10. `deep_link_service._isSiteHost` 是无意义薄包装**

`static bool _isSiteHost(String host) => AppConstants.isSiteHost(host);` 直接删掉、调用处换成 `AppConstants.isSiteHost` 即可，属于负资产。

**11. 正则派生时域选取有逻辑错位**

`_buildSiteUrlRegex` 用的是 `siteRootDomain`（裸域 `nodeloc.com`）+ 可选 `www.` 前缀，但测试只覆盖 `www.` 形态；裸域/子域边界没有用例兜底。`isSiteHost` 又是"主域优先"的写法。两套语义并行，靠测试没覆盖住。

---

### 五、工程与文档

**12. 没有迁移文档**

`docs/` 里没有任何 nodeloc / 站点身份变更说明（现有 22 篇都是渲染、Cookie、编辑器等主题）。这次是"站点身份"这种伤筋动骨的改动，按仓库习惯本该补一篇评估/迁移文档，缺了。

**13. 缺少新工具的单测**

`siteHost`/`siteRootDomain`/`isSiteHost` 这套新派生工具没有任何单元测试，也就没验证"换 baseUrl 后自动生效"这个卖点；测试只是把 linux.do 逐个字面替换成 nodeloc。

---

## 一句话总结

主干思路（域名派生替硬编码）是对的，但执行是"选择性替换"：**深链/剪贴板/Manifest 换了，登录页 hcaptcha、DoH 白名单、l10n 文案、README 没换**；**安全名单被清空**；**测试有 1 条必挂、1 处重复且丢覆盖**。建议 P0 至少补上：修那条 `WWW.LINUX.DO` 测试输入、补裸域用例、迁 login_page 的 sitekey/URL、把 `linuxdo.dart` 明确处置（删或标注存档）。其余（安全名单、l10n、DoH）可作为 P1 明确列入 TODO，而不是无声留白。
