## 三、发现的遗漏与不足

### P0-A（新发现）`UrlHelper.isTrustedImageHost` 仍按 `www.` 精确 host 匹配

**位置**：`lib/utils/url_helper.dart:86-103`（调用点 `lib/utils/link_launcher.dart:219`）

```dart
final siteBase = Uri.tryParse(AppConstants.baseUrl)?.host; // → 'www.nodeloc.com'
if (siteBase != null && siteBase.isNotEmpty) {
  if (host == siteBase || host.endsWith('.$siteBase')) return true;
}
```

**问题**：与刚修好的 `_isMainDomain` **完全同类**的隐性回归（`复盘2.1` 未覆盖）。实际覆盖范围退化为「`www.nodeloc.com` + `*.www.nodeloc.com`」：

| host | 期望 | 实际 |
|---|---|---|
| `www.nodeloc.com` | 可信 | ✅ |
| `nodeloc.com`（裸域） | 可信 | ❌ |
| `cdn.nodeloc.com`（兄弟子域） | 可信 | ❌ |
| `foo.www.nodeloc.com` | —— | ✅（现实中不存在） |

**影响**：正文里指向裸域 / 子域的图片直链（`https://nodeloc.com/uploads/x.png`）被判「非本站可信图」→ 不走内置图片查看器，改为弹「即将离开外部网站」确认框。触发面小，但属 P0 身份口径不一致。

**修复建议**：站点判定改为 `AppConstants.isSiteHost(host)`，CDN / S3 CDN 仍保留精确 host 匹配。

---

### P0-B（新发现）`create_topic_page._isSameSiteUrl` 只认精确 `www.`

**位置**：`lib/pages/create_topic_page.dart:574-578`

```dart
bool _isSameSiteUrl(TitleUrlInfo candidate) {
  final siteHost = Uri.tryParse(AppConstants.baseUrl)?.host; // 'www.nodeloc.com'
  if (siteHost == null || siteHost.isEmpty) return false;
  return candidate.uri.host.toLowerCase() == siteHost.toLowerCase();
}
```

**问题**：标题里的 URL 若指向裸域 `nodeloc.com` 或子域，会被当成「外部链接」→ 触发 onebox 取标题 + 写成 `featured_link`，与 Discourse 官方「仅外部链接才做精选链接」语义相反。

**影响**：轻（不崩、不丢数据），属身份口径不一致；与 P0-A 同一根因。

**修复建议**：改为 `AppConstants.isSiteHost(candidate.uri.host)`（空 host 仍返回 false）。

---

### P0-C（新发现）Android 只登记 `www.nodeloc.com`，裸域链接系统层接不住

**位置**：`android/app/src/main/AndroidManifest.xml:56-94`

Dart 侧 `isSiteHost('nodeloc.com') == true`，但 Manifest 只声明 `android:host="www.nodeloc.com"`。用户分享/点击**裸域**链接 `nodeloc.com/t/123` 时，系统不会把 intent 派给 App（浏览器先打开再 301 到 www），Dart 侧判定再准也无从生效。NodeLoc 裸域 301 到 www，而中文社区分享裸域链接很常见。

**修复建议**：补 `nodeloc.com` 的 `/t/`、`/u/`、`/session/email-login/`（http/https）共 3 组 filter。注意 `autoVerify` 需站方 `assetlinks.json` 同时覆盖该 host；若不覆盖，保持「App 内可处理、系统不自动接管」的降级语义即可（不加 `autoVerify`）。

---

### P0-D（新发现）Flatpak 版缺 `discourse://` scheme 注册

**位置**：`flatpak/com.github.lingyan000.fluxdo.desktop:9`（对照 `linux/runner/fluxdo.desktop:9`）

```
# flatpak
MimeType=x-scheme-handler/fluxdo;
# linux/runner
MimeType=x-scheme-handler/fluxdo;x-scheme-handler/discourse;x-scheme-handler/https;
```

**影响**：**Flatpak 用户走 User API Key 授权登录时，`discourse://auth_redirect?payload=…` 回调打不开 App**，登录链路断在最后一步。属深链身份配置缺失（入口在 P2，但配置属 P0 深链范畴）。

**修复建议**：Flatpak desktop 文件补 `x-scheme-handler/discourse`。

### P0-E（`复盘2.1` 已列，但影响被低估）Rust 侧 ECH 内置域未更新 → ECH 对新站**静默完全失效**

**位置**：`core/doh_proxy/src/ech_dns_policy.rs:6`

```rust
const BUILTIN_DOMAINS: [&str; 2] = ["linux.do", "ldstatic.com"];
```

**我核了完整链路**：

1. Dart `EchDnsPolicy.toJson()` **只发送 `custom_domains`**（`lib/services/network/doh/ech_dns_policy.dart:56-59`）；
2. Dart `fromJson` 会把「被 builtin 覆盖的域」过滤掉（L66-69），而 Dart builtin 现在是 `nodeloc.com`；
3. 因此 `nodeloc.com` **永远进不了 `custom_domains`**；
4. Rust `query_name('nodeloc.com')` 既不命中 `BUILTIN_DOMAINS`（linux.do/ldstatic），也不命中 custom → 返回原域名，**不做 ECH 查询名替换**。

**结论**：这不是「常量过期」，而是 **ECH 域名增强对新站点 100% 不生效**（Dart 侧改了等于没改）。归为 P1 可以，但风险描述应升级，且必须与 Rust 重编 `.so` 同批处理。

### 部署前提（非代码缺陷，但决定深链体验）

- `https://www.nodeloc.com/.well-known/assetlinks.json` → **404**：Android `autoVerify` 无法通过，http(s) 深链实际不接管。
- `apple-app-site-association` 仅列官方 App `JU847GN98N.com.nodeloc.app`：本应用拿不到 Universal Links。
- iOS 无 `associated-domains` entitlement：iOS 侧 Universal Links 从未生效，只有 custom scheme。

三项叠加 ⇒ **Android/iOS 的 http(s) 深链实际都接不住，只有 `fluxdo://` / `discourse://` 生效**。需站方配合，属验收前提。
