## 四、发现的遗漏与不足

### 🔴 P0-新1｜Rust 子模块未提交 → ECH 修复**根本没进仓**，CI 仍编译旧站代码

**位置**：`core/doh_proxy`（git 子模块，上游 `Lingyan000/fluxdo_doh`）

```
git submodule status              → 660a19b… core/doh_proxy (heads/main)
git diff --submodule=short -- core/doh_proxy
-Subproject commit 660a19b3ba49d26933f25486705ba85c0e74292b
+Subproject commit 660a19b3ba49d26933f25486705ba85c0e74292b-dirty
```

Rust 改动（`src/ech_dns_policy.rs`、`src/dns.rs`、`tests/cloudflare_ech.rs`、`README.md`）
**只存在于子模块工作区，未 commit**；主仓记录的指针仍是旧 commit `660a19b`。

**叠加事实**：
1. `.gitignore:60` 含 `android/app/src/main/jniLibs/` → `git ls-files android/app/src/main/jniLibs` 为**空**，本机重编的 `.so` **不入库、不随包发布**；
2. `build.yaml` 用 `submodules: recursive` 检出，Android job 实际执行
   `dart tool/flutterw.dart build apk --release` 并校验
   `unzip -l … | grep "lib/${arch}/libdoh_proxy.so"` → **`.so` 由 CI 从子模块源码现场编译**。

**结论链**：
> 现在提交主仓 → 子模块指针不变 → CI 检出旧 Rust 源码 → 编译出
> `BUILTIN_DOMAINS = ["linux.do","ldstatic.com"]` → Dart 侧 `builtinDomains`
> 已派生为 `nodeloc.com` 并会把被 builtin 覆盖的域从 `custom_domains` 过滤掉
> → `nodeloc.com` 永远进不了 `custom_domains` → **ECH 对新站 100% 静默失效**。

复盘1.2 §8.3 第 1 条虽提到「Rust 是子模块、需提交并 push 上游」，但同文 §8.1 把状态
记成「重编 arm64 `.so` 并部署」，属**事实性误记**——`.so` 在 `.gitignore` 里，根本不会进入发布产物。

### 🔴 P0-新2｜Windows 缺 `discourse://` scheme 注册 → User API Key 授权登录回调断链

**位置**：`windows/fluxdo_url_scheme.reg`（改动前）

```reg
[HKEY_CURRENT_USER\Software\Classes\fluxdo]
@="URL:FluxDO Protocol"
"URL Protocol"=""
```

**全仓核查**：`git ls-files '*.reg'` 只有这一个文件，
`git grep -E 'Software\\Classes|URL Protocol' -- windows` 也只有它 →
**Windows 唯一的 scheme 注册入口只注册了 `fluxdo`，没有 `discourse`**。

而 `windows/runner/main.cpp:15` 明确解析命令行里的 `discourse://` ——
App 会处理，系统却**从不路由**给它 → Windows 用户走 User API Key 授权登录时，
`discourse://auth_redirect?payload=…` 打不开 App，**登录断在最后一步**。

**与 P0-D 完全同类**：复盘1.2 发现 Flatpak 缺 `x-scheme-handler/discourse` 并已修复，
**同类问题在 Windows 上被漏掉了**。

**安装器额外发现**：`windows/setup.iss` **无 `[Registry]` 段、也不导入 `.reg`**
→ 连 `fluxdo://` 都只能靠用户手动双击 `.reg` 注册，**开箱即无效**。

### 6.2 A2：Windows `discourse://` 注册（`.reg` + 安装器）

**`windows/fluxdo_url_scheme.reg`**：
- 新增 `[HKEY_CURRENT_USER\Software\Classes\discourse]` 及其
  `shell\open\command`（与 `fluxdo` 同指向 `fluxdo.exe "%1"`）；
- 文件头注释补齐两 scheme 的用途与「安装包已自动写入，本文件供便携/手动场景」的说明。

**`windows/setup.iss`**：新增 `[Registry]` 段，安装时自动注册两个 scheme：

```iss
[Registry]
Root: HKA; Subkey: "Software\Classes\fluxdo"; ValueType: string; ValueName: ""; ValueData: "URL:FluxDO Protocol"; Flags: uninsdeletekey
Root: HKA; Subkey: "Software\Classes\fluxdo"; ValueType: string; ValueName: "URL Protocol"; ValueData: ""; Flags: uninsdeletekey
Root: HKA; Subkey: "Software\Classes\fluxdo\shell\open\command"; ValueType: string; ValueName: ""; ValueData: """{app}\{#MyAppExeName}"" ""%1"""
Root: HKA; Subkey: "Software\Classes\discourse"; ValueType: string; ValueName: ""; ValueData: "URL:Discourse Protocol"; Flags: uninsdeletekey
Root: HKA; Subkey: "Software\Classes\discourse"; ValueType: string; ValueName: "URL Protocol"; ValueData: ""; Flags: uninsdeletekey
Root: HKA; Subkey: "Software\Classes\discourse\shell\open\command"; ValueType: string; ValueName: ""; ValueData: """{app}\{#MyAppExeName}"" ""%1"""
```

设计说明：
- **写 `HKA`（HKCU 映射）而非 HKLM**：安装器 `PrivilegesRequired=lowest`（免管理员），
  HKLM 写不进去，HKCU 对当前用户即可生效；
- **`Flags: uninsdeletekey`**：卸载时清理注册表，不留孤儿协议键；
- **`{app}` 展开为实际安装目录**（默认 `{autopf}\FluxDO`），修复了原 `.reg`
  硬编码 `C:\Program Files\FluxDO` 与免管理员安装路径（`{localappdata}\Programs\…`）不符的问题；
- 安装器自动注册后，**`fluxdo://` 首次实现开箱即用**（原先也只靠手动 `.reg`）。
