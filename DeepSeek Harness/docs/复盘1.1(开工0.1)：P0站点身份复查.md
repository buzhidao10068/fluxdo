## 二、发现的遗漏与不足

### ⚠️ 缺陷 1（P0 范畴内，复盘漏报）：`dio_http_client._isMainDomain` 主域判定不一致

**位置**：`lib/services/dio_http_client.dart:101-111`

```dart
/// 提取 [AppConstants.baseUrl] 的 host(例如 `linux.do`),用于判断主域。
static final String _mainHost = Uri.parse(AppConstants.baseUrl).host; // → 'www.nodeloc.com'

bool _isMainDomain(Uri url) {
  final host = url.host;
  if (host.isEmpty) return false;
  // 主域精确匹配 或 是主域的子域(*.linux.do)
  return host == _mainHost || host.endsWith('.$_mainHost');
}
```

**问题**：baseUrl 从裸域 `linux.do` 改成 `www.nodeloc.com` 后，`endsWith('.$_mainHost')` 的实际语义从 `*.linux.do` 变成了 `*.www.nodeloc.com`，覆盖范围**反而变窄**：

| host | 期望（本站） | 实际判定 |
|---|---|---|
| `www.nodeloc.com` | 主域 | ✅ main |
| `nodeloc.com`（裸域） | 本站 | ❌ 判为 CDN/外域 |
| `cdn.nodeloc.com`（兄弟子域） | 本站 | ❌ 判为 CDN/外域 |
| `foo.www.nodeloc.com` | —— | ✅ main（但现实中不存在这种域） |

**影响**：`DioHttpClient` 是 `flutter_cache_manager` / 图片下载的 `http.Client`。`_isMainDomain` 决定走 `_mainDomainDio`（带 cookie，供 `/uploads/secure-uploads/*` 私密图、`user_avatar` 鉴权）还是 `_cdnDio`（完全不带 cookie 的省 IO 通道）。若私密图/头像 URL 落在裸域或子域，会走无 cookie 通道 → **403**。当前 NodeLoc 无独立静态 CDN、资源基本走 `www.nodeloc.com`，所以是**潜在风险而非现网必现**；但与 `cookie_jar_service.matchesAppHost`、`AppConstants.isSiteHost`、`link_launcher.isInternalUrl` 的「按根域匹配」策略**直接矛盾**，属实现不一致。

**修复建议**：改用已存在的 `AppConstants.isSiteHost(host)`，消除第二份域名匹配逻辑。

### ⚠️ 缺陷 2（P0 相邻，复盘已识别但未纳入本步）：Rust 侧 ECH 内置域未更新

**位置**：`core/doh_proxy/src/ech_dns_policy.rs:6`

```rust
const BUILTIN_DOMAINS: [&str; 2] = ["linux.do", "ldstatic.com"];
```

Dart 侧已改（`ech_dns_policy.dart:12`），但编译进 `libdoh_proxy.so` 的 Rust 常量仍是 linux.do / ldstatic.com。属待办第 3 步（P1）范畴，但它是**编译产物里硬编码的站点身份**，建议与 Rust ECH 修复同批处理并重编 `.so`。

### 观察 3（部署前提，非代码缺陷）：App Links / Universal Links 服务端文件

- Android `autoVerify="true"` 要真正生效，需 `nodeloc.com/.well-known/assetlinks.json` 由站方托管；否则只保留「App 内可处理，系统不自动接管」的降级行为。
- iOS 无 `associated-domains` entitlement，当前深链只靠 custom scheme（`fluxdo://`、`discourse://auth_redirect`）。若要做系统级 Universal Links，需加 entitlement 并由站方托管 AASA。
- 属发布/站方协作项，不在本次代码验收范围，但会影响「深链是否无感」的体验验收。

### 观察 4（无功能影响，属后续步骤）：散落注释仍写 linux.do

`dio_http_client.dart:17/22/102/109`、`cookie_jar_service.dart:53/119/129`、`session_cookie_sentinel.dart:565`、`_uploads.dart:426`（"linux.do 4MB"）、`user.dart:234` 注释等，均为**注释或 P3/P4 范围的生态代码**，无逻辑影响，建议在对应步骤一并清理（P3 删生态、P4 文案/注释）。

### 观察 5：`link_security.dart` 死代码判断需修正

复盘1.3 称 `lib/utils/link_security.dart` 的 `isLocalIp` 是死代码 —— **该结论对**（`grep isLocalIp` 仅定义处 1 条，0 调用者）。但注意**整个文件不是死代码**：`link_launcher.dart:75` 调用了 `LinkSecurity.checkUrl`。P3 清理时不要整文件删除，只删 `isLocalIp` 方法与已失效的配置字段。
